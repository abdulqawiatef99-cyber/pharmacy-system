## 2. نقل الـ SHA المقبول إلى `main`

`feature/reference-catalog` محتفظ بالـ 12 تعديل اللي على `main` (`25328e3`)، فمفيش حاجة هتضيع في الطريقتين.

### 2-أ. المقترح: release PR (من غير إعادة كتابة `main`)
بيخلي محتوى `main` **مطابق بالظبط** للـ SHA المقبول، من غير force push. ده مهم لأن بوابة النشر
(`.github/scripts/verify_push.sh`) **بترفض أي force push** وما بتنشرش المثبّت، والحارس (`branch-guard.yml`) بيفتح Issue.
اتجربت محليًا 2026-11-11 على `develop` @ `4a93eb2` و`main` @ `25328e3`: محتوى `main` بعد الدمج = `develop` بالظبط، ومن غير force.

```bash
ACCEPTED=<accepted develop sha>
git fetch origin
git checkout -b release/v0.4.0 "$ACCEPTED"
git merge -s ours origin/main -m "release v0.4.0: main takes develop @ ${ACCEPTED:0:7} (#20, #104 option 1)"
git diff --quiet "$ACCEPTED" HEAD && echo "tree == accepted"        # must print
git merge-base --is-ancestor origin/main HEAD && echo "no force needed" # must print
git push origin release/v0.4.0
# PR release/v0.4.0 -> main. CI linux + windows run on it (a PR into main runs Windows: part of the approved release).
```
- **إنت بس** اللي تدوس Merge، وبـ **"Create a merge commit"** (مش squash ولا rebase).
- بعد الدمج: `git fetch origin main` الأول (الـ `origin/main` المحلي لسه قديم)، وبعدين `git diff --quiet "$ACCEPTED" origin/main` لازم ينجح، و`git rev-parse origin/main^2` = آخر commit في `release/v0.4.0`.
- **تحذير لبعد الإطلاق:** ماحدش يدمج `main` في `develop`. التعديلات الـ 12 بقت في تاريخ `main` من غير محتواها، فدمج عكسي يخلي git يفتكرها اتدمجت. الكتالوج يرجع من `feature/reference-catalog` لـ `develop` مباشرة (أو بعد إعادة ترقيم الـ migrations)، والإصدار الجاي `develop → main` عادي.

### 2-ب. البديل: إعادة ضبط `main` (محتاج موافقة منفصلة)
```bash
git push --force origin "$ACCEPTED":refs/heads/main
```
النتيجة المتوقعة: الحارس يفتح Issue ويحفظ `guard/main-25328e3c7851`، و**بناء المثبّت يرفض النشر** (force push).
فلازم بعده PR تاني صغير يندمج في `main` عشان يتنشر `installer-latest`. خطوات أكتر ومخاطرة أكتر، عشان كده 2-أ هو المقترح.

## 8. أسبوع جنب E-Stock
- E-Stock يفضل شغال وهو المرجع لمدة **أسبوع تقريبًا**. البرنامج الجديد يشتغل جنبه.
- آخر كل يوم: قارن مبيعات اليوم والخزنة بين الاتنين. أي فرق = Issue جديدة فيها الرقمين، ومفيش تعديل في البيانات بإيد.
- بعد الأسبوع **إنت** اللي تقرر إمتى توقف E-Stock. لحد ساعتها `main` ما يتحركش غير بإصلاح متجرب وموافقتك.

ده آمن **بس** لو مفيش migration أو تغيير مكتبات بين النسختين:
```bash

```
لو مش فاضي، النسخة القديمة ممكن ما تفهمش القاعدة: روح للمستوى 2.

**المستوى 2 — البرنامج القديم + البيانات:** الاسترجاع بيرجّع البيانات بس، مش البرنامج. لو البرنامج الجديد فضل متثبت، أول ما يفتح هيطبّق الـ migrations بتاعته على البيانات المسترجعة تاني. فالترتيب:
1. ثبّت **ملف التثبيت القديم** من الفلاشة، وفي آخر شاشة **شيل علامة «افتح البرنامج دلوقتي»** قبل Finish.
2. أنا بقفل أي نسخة شغالة (السيرفر بيفضل شغال في الخلفية حتى لو المتصفح اتقفل)، وبعدين أسترجع **بالبرنامج القديم**، وبعدين أتأكد:

## 10. ليلة النقل: قاعدة فاضية + نقل قاعدة إي ستوك كلها (#113، F91)

كل خطوة بتكتب PASS أو FAIL في ملف، وأول FAIL بتوقف كل حاجة. ملفات النقل كلها (فيها أسامي وأرصدة حقيقية) بتتكتب هنا بس، مش في «المستندات»:

### أ. قبلها بيوم أو الضهر: التجربة (إي ستوك شغال عادي)
1. «أدوات الصيدلية» ← `estock-db-read.bat`: قراية بس، إي ستوك ما بيتغيّرش. آخرها بيفتح `summary.txt`، وفيه سطر `RESULT:` لازم يبقى `PASS` (أو `PARTIAL`، والنقل بيكمّل الجداول الناقصة لوحده).
2. «أدوات الصيدلية» ← `estock-db-import.bat`. البرنامج لسه فيه بيانات التجربة (بيع وحركات مخزون)، والنقل الحقيقي بيرفض أي قاعدة فيها بيانات. فالسكربت بيعمل لوحده **تجربة على قاعدة جديدة فاضية** في فولدر مؤقت («REHEARSAL»): قاعدة البرنامج ما بتتفتحش ومفيش حاجة بتتكتب فيها، والتقارير بس اللي بتفضل. مابيسألش YES، وبيقول في الآخر إنها تجربة بس. (لو القاعدة فاضية، بيجرب على نسخة منها وبيسأل YES: **اكتب أي حاجة غير YES**.)
3. اقرا `owner-report.txt` (بيتفتح لوحده في «المفكرة»):
   - أول سطر: النتيجة.
   - القسم ١ «محتاج قرارك أو تأكيدك»: رد على كل سطر هنا أو في #113.
   - القسم ٢ «المطابقة»: لازم يبقى «عدم مطابقة: مفيش».

   **الملف لازم يبقى موجود قبل ما تشغّل `estock-db-import.bat`**: السكربت بيقراه أول ما يبدأ بس. لو عملته أو غيّرته وهو مستني YES، اكتب أي حاجة غير YES وشغّله تاني (السكربت بيرفض ينقل لو الملف ظهر بعد التجربة).

2. **اقفل شيفت إي ستوك الأول** (قفل الخزنة). فلوس الدرج (نقطة بيع 1) مش حساب في البرنامج؛ المبلغ اللي اتعد يبقى **نقدية أول شيفت** في البرنامج. رصيد الخزينة في إي ستوك رقم مرجع بس (قرار المالك 20/11)، وحسابها في البرنامج بيبدأ بصفر.
3. **اقفل برنامج إي ستوك** على كل الأجهزة. ماتقفلش «إس كيو إل سيرفر» (القراية محتاجاه شغال).
4. «أدوات الصيدلية» ← `estock-db-read.bat`: **القراية النهائية**، وإي ستوك مقفول. لو رقم تشغيلة موجود مرتين في إي ستوك نفسه: لو السطرين زي بعض بيتحسب مرة واحدة، ولو مختلفين النقل بيقف ويعرض السطرين، والمالك يختار السطر الصح في `packs.json` (`"duplicates": {"<رقم التشغيلة>": 1 أو 2}`).
5. لو البرنامج فيه بيانات التجربة: «أدوات الصيدلية» ← `launch-fresh-start.bat`:
   - بيسأل اسم الصيدلية زي ما هو على الشاشة.
   - بيغيّر اسم فولدر البيانات لـ `data-trial-<التاريخ-الوقت>` (مفيش مسح)، بعد نسخة احتياطية متأكد منها.
   - المطلوب: شاشة أول تشغيل، واملاها وافتكر اسم المالك.
   - النتيجة في `%USERPROFILE%\Documents\launch-night\fresh-start.txt`، وآخر سطر `PASS - ALL DONE`.
   - بعدها الإعدادات في (ب-2) تحت.
6. «أدوات الصيدلية» ← `estock-db-import.bat`:
   - بياخد أحدث قراية كاملة، ولو فيها جداول ماتقريتش بيقراها لوحدها الأول.
   - يسأل اسم المالك وكلمة المرور (مرتين، الكتابة مش بتظهر).
   - يقفل البرنامج بس، ويجرب على نسخة، ويفتح `owner-report.txt`.
   - اقرا القسم ١ والقسم ٢. لو «عدم مطابقة: مفيش» وكل اللي في القسم ١ متفق عليه، اكتب `YES`.
   - بعد YES: نسخة احتياطية متأكد منها، ثم النقل، ثم فحص المخزون، ثم البرنامج يفتح تاني.
   - النتيجة في `estock-db-import.txt`، وآخر سطر `PASS - ALL DONE - program started again`.

### ب-2. الإعدادات اللي بتتعمل تاني على القاعدة الجديدة (بعد شاشة أول تشغيل)
القاعدة الجديدة فاضية، فإعدادات الطابعات والإيصال والموظفين **مش بتتنقل** (اللي بيتنقل لوحده بس: نسخة البرنامج، وإعداد الموبايلات على الواي فاي، وإعداد النسخ الاحتياطي). موظفين إي ستوك بيتنقلوا **مستخدمين متوقفين** بأساميهم بس، عشان الفواتير القديمة، ومن غير كلمات السر. من «الإعدادات»، علّم على كل سطر:
- [ ] **طابعة الإيصال:** اختار الطابعة المباشرة، وفعّل «فتح الدرج عند تحصيل نقدي». جرّب «فتح الدرج تجربة»: الدرج لازم يفتح.
- [ ] **طابعة الملصقات:** اختار طابعة الملصقات ومقاس الملصق، واعمل «معايرة بكرة الملصقات»، وبعدين اطبع «ملصق تجربة»: الكلام في نص الملصق ومفيش ملصق فاضي زيادة.
- [ ] **رأس الإيصال:** اسم الصيدلية والعنوان والتليفون، و**اللوجو**، والكود **QR** (لو بتستخدمه). اطبع إيصال تجربة وبص عليه.
- [ ] **حسابات الموظفين والصلاحيات:** اعمل حساب لكل موظف بدوره (كاشير / صيدلي / مدير)، وراجع الصلاحيات (سعر الشراء مخفي عن الكاشير، وحد الخصم).
- [ ] **فولدر النسخ الاحتياطي:** في صفحة النسخ الاحتياطي اتأكد إن الفولدر اللي خارج الجهاز (أو `D:`) لسه هو نفسه ومكتوب جنبه إنه شغال.

### ج. بعد النقل على طول
- **أول حاجة:** «النسخ الاحتياطي» ← «اعمل نسخة الآن»، واتأكد إن «آخر نسخة خارج الجهاز» اتغيّرت لتاريخ ووقت النهارده. لو لسه قديم أو فيه مشكلة، ماتبدأش البيع قبل ما تقولّي.
- قارن عدد الأصناف ورصيد 3 أصناف تعرفهم مع إي ستوك. إي ستوك يفضل موجود للرجوع ليه (القسم 8).

اللي هتلاقيه في البرنامج بعد النقل (ومش غلط):
- **مخزن 2 (مستشفيات الحكمة):** بضاعته ملك المستشفى، فمش داخلة في مخزون الصيدلية ولا قيمته. أصنافها وكمياتها وصلاحيتها وقيمتها في `hospital-stock.csv` في تقارير النقل. علامة «ملك المستشفى» جاهزة في المثبّت (0039) وبتتشغّل بعد ما الجرد والتسويات والتكلفة يفرّقوا الملكية؛ لحد كده هي مش في البرنامج.
- **«0000»** (في خزن إي ستوك) مالوش حساب في البرنامج: تاريخه في الأرشيف، ولو عليه رصيد بيطلع سطر في القسم ١.
- **المورد «جرد»** اتنقل مورد عادي باسم **«مصادر متفرقة (جرد)»** برصيده وتاريخه.
- **العميل «الصيدلية»** اتنقل **حساب داخلي** (استهلاك الصيدلية) برصيده وتاريخه، ومش داخل في إجمالي العملاء الحقيقيين.
- **الحكمة (شبين وميت خلف):** عملاء برصيدهم وكل تاريخهم زي إي ستوك.
- **الفواتير القديمة** (بيع ومرتجع وشراء) وكشوف الحساب وقفل الشيفتات والنواقص: محفوظة في `estock-archive.sqlite` جنب قاعدة البيانات، وجوه كل نسخة احتياطية. مكتوب عليها «إي ستوك» كمصدر. شاشاتها بتتعمل دلوقتي.
- **الخزنة والمحافظ** (`Cash_depots`): على نسخة المثبّت بتتنقل حسابات في البرنامج برصيدها الافتتاحي من إي ستوك (الخزنة الرئيسية، البنك، إنستاباي، فودافون كاش، ...)؛ اعدّها بعد النقل وسجّل أي فرق بالجرد. درج الشيفت مش حساب.

### د. بعد النقل: أرصدة الموردين والعملاء الحقيقية
الأرصدة اتنقلت زي إي ستوك (أو زي اللي أكدته في `openings-confirmed.xlsx`). الرصيد الحقيقي لكل مورد وعميل **بتأكده إنت من البرنامج** بعد النقل:
- الفرق بيتسجل **تسوية افتتاحية** في حسابه، مش دفع ولا مصروف، ومتسجل في سجل العمليات باسمك.
- الخدمة جاهزة (للمالك بس)، والشاشة بتتعمل دلوقتي (F108).
- لحد ما الشاشة تنزل: أي رصيد عايز تصححه قبل البيع، اكتبه في `openings-confirmed.xlsx` **قبل ما تشغّل `estock-db-import.bat`** (يعني قبل YES بكتير، مش وهو مستني). بعد النقل الملف مابيتقريش تاني.
- ابدأ بالأكبر قيمة، وهم أول القايمة في `openings-to-confirm.xlsx`.

### الرجوع للبيانات القديمة
- بيانات التجربة كاملة في `%LOCALAPPDATA%\PharmacyPlatform\data-trial-<التاريخ-الوقت>`.
- نسخة البداية من الصفر في `%LOCALAPPDATA%\PharmacyPlatform\backups\fresh-start-<التاريخ-الوقت>`.
- النسخة الاحتياطية اللي قبل النقل اسمها مكتوب في `estock-db-apply.txt`.
- لو النقل وقف في النص: نفس الأمر بنفس القراية بيكمّل من الخطوة اللي وقفت، ومفيش حاجة بتتكتب مرتين.
- الرجوع قرارك، وأنا اللي بعمله.

### الطريق القديم (ملفات إكسيل، احتياطي بس)
`estock-import.bat` بياخد تقريرين إكسيل من إي ستوك («قائمة الأصناف» و«كميات الأصناف طبقًا لتواريخ الصلاحية» لمخزن الصيدلية) من `C:\estock`. بينقل الأصناف والرصيد بس، من غير عملاء ولا موردين ولا تاريخ. مايتستخدمش ليلة النقل إلا لو `estock-db-read.bat` مش شغال خالص، وبعد ما تقولّي.

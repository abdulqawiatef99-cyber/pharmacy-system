# اختبار القبول على Windows والأجهزة

> **قرارك:** الكاشير الجديد **في مرحلة اختبار**، وكاشير E-Stock فاضل هو الشغال فعليًا لحد ما كل البنود اللي تحت تنجح على جهاز الصيدلية، وبعدها تاخد قرار الانتقال بنفسك.

## 1. ما اتختبر أوتوماتيك (على Linux، في البيئة دي)
- كل منطق البيع: إن الأقرب صلاحية بيتصرف الأول، وسعر التشغيلة، ومنع بيع المنتهي، والكميات اللي مش متاحة، والخصم بالصلاحيات، والآجل وحد العميل، والمرتجع، والإلغاء، والخزنة وقفلها، وإن مفيش حاجة بتتسجل مرتين لو حصلت إعادة محاولة، والضغط المزدوج على الزرار، وسجل التدقيق. الاختبارات في `tests/test_sales.py` و`tests/test_cashier_acceptance.py`.
- أوامر الطابعة الحرارية (ESC/POS raster) وفتح الدرج: الأوامر بتتبني وتتبعت لطابعة شبكة **وهمية** (socket محلي) أو لملف.
- الإيصال العربي كصورة: الحروف بتتشكل صح على Linux (Pillow + raqm).
- الواجهة في Chromium: الكاشير، والجرد بمقاس موبايل، والإيصال.

## 2. ما اتختبر على Windows فعلًا
**لا شيء لحد دلوقتي.** البيئة هنا Linux بس. البنود دي محتاجة تتعمل على جهاز الصيدلية.

## 3. خطوات الاختبار على جهاز الصيدلية (حوالي 30 دقيقة)
| # | الخطوة | النتيجة المطلوبة | ✓ |
|---|---|---|---|
| 1 | `scripts\windows\install.bat` | آخر سطر يكون `SELFTEST PASSED` وعدد الاختبارات اللي نجحت مكتوب قبله | |
| 2 | ابعتلي ناتج `python manage.py selftest --quick` | لو سطر `arabic_shaping(raqm)` فيه FAIL، الإيصال هيتطبع من المتصفح بدل الطباعة المباشرة (التفاصيل في البند 4) | |
| 3 | `python manage.py init ...` بعدين `start.bat` | المتصفح يفتح على صفحة الدخول | |
| 4 | قارئ الباركود: افتح الكاشير، حط المؤشر في خانة البحث، وامسح علبة | الصنف يتضاف مرة واحدة بس. **لو اتضاف مرتين يبقى القارئ بيبعت Enter مرتين، ولازم يتظبط من إعداداته** | |
| 5 | طباعة من المتصفح: بيع تجريبي، وبعدين الإيصال | إيصال بعرض 80مم، والعربي مقروء، ومفيش صفحة فاضية زيادة. في إعدادات الطباعة في Chrome: الهوامش "None" والحجم 80mm | |
| 6 | طباعة مباشرة: `set PHARM_PRINTER=win:اسم الطابعة كما في Windows` ثم `python manage.py selftest --quick --print-test` | إيصال اختبار مقروء | |
| 7 | الدرج: `selftest --quick --print-test --drawer-test` | الدرج يفتح. **الدرج لازم يكون متوصل بالطابعة بكابل RJ11** | |
| 8 | قطع النت أثناء البيع | البيع يكمل عادي (البرنامج محلي ومش محتاج نت) | |
| 9 | اقفل البرنامج (أو اقفل الجهاز) وهو في نص فاتورة | لما تفتحه تاني الفاتورة تبقى يا إما مسودة يا إما مكتملة، **ومفيش حالة في النص**. وبعدها `python manage.py verify` يطلع OK | |
| 10 | `backup.bat` وبعدين `python manage.py verify backups\...zip` | يطلع OK | |
| 11 | استرجاع على جهاز تاني (أو مجلد تاني) | البيانات وملفات الفواتير ترجع كاملة | |
| 12 | الموبايل على نفس الواي فاي: `python manage.py serve --host 0.0.0.0` | الصفحات تفتح. **الكاميرا كقارئ باركود مش هتشتغل غير بـ HTTPS** (مرحلة لاحقة) | |

## 4. حاجات معروفة قبل ما تختبر
- **تشكيل الحروف العربية في الطباعة المباشرة على Windows:** حسب توثيق Pillow، تشكيل الحروف العربية على Windows محتاج مكتبة FriBiDi تتثبت لوحدها ([Pillow issue #7126](https://github.com/python-pillow/Pillow/issues/7126)). من غيرها الإيصال المطبوع كصورة هيطلع حروفه مقطعة. البرنامج **بيكتشف ده لوحده** وبيرجع للطباعة من المتصفح (المتصفح بيعرض العربي سليم). الحل: نحط `fribidi.dll` جنب ملف Python الأصلي (مكانه بيطلع من `sys._base_executable`)، وبعدين `selftest` يتأكد إن الموضوع اتحل. **ما اتجربش.**
- **الطابعة بالـ USB على Windows:** بتتعامل كأنها طابعة Windows عادية (`win:`) ومحتاجة `pywin32`، وده بيتثبت مع `install.bat`. **الطريقة دي ما اتختبرتش.**
- البرنامج **ميقدرش** يتحكم في الطابعة من الموبايل مباشرة، فالطباعة دايمًا بتتم من جهاز الصيدلية اللي الطابعة متوصلة بيه.

## 5. اللي محتاجه منك
موديل الطابعة الحرارية، ونوع توصيلها (USB أو شبكة)، وهل الدرج متوصل بيها، ونتيجة البنود من 1 لـ 12.

# Architecture Decision Records

Each decision: context → decision → consequences. New decisions are appended; an
outdated one is marked *Superseded by ADR-xxx*, never deleted.

## ADR-001 Modular monolith, not microservices (2026-10-24)
**Context.** One developer-owner, one pharmacy at start, many future tools that share
items, suppliers, stock and users.
**Decision.** One deployable application, split into modules (`core`, `catalog`,
`inventory`, `purchasing`, …) with one shared database. Modules talk through service
functions, never by reaching into another module's tables for writes.
**Consequences.** Simple deploy/backup/debug; transactions span modules (approve invoice
+ stock + cost + audit atomically). A module can be extracted into a service later if
load or team size demands it; the API contract stays the same.

## ADR-002 SQLite on the pharmacy node now, PostgreSQL centrally later (2026-10-24)
**Context.** The owner needs the system on the pharmacy Windows PC, working offline
(internet in Egypt drops). The build environment for this phase also blocks PyPI, so no
PostgreSQL driver could be installed or tested here.
**Decision.** SQLite (WAL, `synchronous=FULL`, foreign keys on, `BEGIN IMMEDIATE` for
writes). SQL kept close to ANSI; no SQLite-only features in business logic except
triggers that enforce append-only tables (re-implementable in PostgreSQL).
**Consequences.** Zero-admin install, one-file backup (`manage.py backup`, online-safe),
full offline. Single writer at a time — fine for one pharmacy with a few users. For the
multi-pharmacy SaaS: central PostgreSQL + per-node sync (uuid7 ids make that possible).
**Revisit when:** first second-pharmacy customer, or >5 concurrent writers.

## ADR-003 Money and percentages as integers (2026-10-24)
Money = INTEGER piasters (1 EGP = 100). Percent = INTEGER basis points (12.5% = 1250).
Unit cost (needs fractions of a piaster) = Decimal string, 6 dp, computed with
`decimal.Decimal`. No floats anywhere in financial paths.

## ADR-004 UUIDv7 identifiers (2026-10-24)
Time-ordered (index friendly) and globally unique, so records created offline on
different devices/branches never collide when synced.

## ADR-005 Immutable stock ledger + moving weighted average cost (2026-10-24)
`stock_movements` is append-only (DB triggers reject UPDATE/DELETE). Corrections are
reversing movements. `stock_balances` is a cache updated in the same transaction and
provably consistent (`inventory.verify_balances`, `manage.py verify`). Cost method:
moving weighted average per item per branch. Batches (تشغيلات) are first-class with
their own expiry and public price (Egyptian price rises: old batches keep old legal price).

## ADR-006 Bonus stock is free stock (2026-10-24)
Paid qty + bonus qty both enter stock; the line amount is spread over all of them, so
bonus lowers unit cost. Invoice-level extra discount/tax is allocated to lines
proportionally to line value.

## ADR-007 AI reads, never decides (2026-10-24)
Vision model output is tagged `source=ai`, confidence capped at 0.9; any field < 0.8
blocks approval until a person confirms it. Matching, arithmetic, totals reconciliation
and stock posting are deterministic code. Only the invoice image is sent to the AI
provider (no customer/patient data). Metered per organization via `usage_counters`.

## ADR-008 Matching levels (2026-10-24)
barcode → supplier code → learned alias → fuzzy. Fuzzy matches become `auto` only when
name ≈ identical AND strength, form, pack count, pack content and modifiers (Extra, XR,
Forte…) all agree; otherwise `suggested` and a human must click. Aliases are learned
only from human confirmations, per supplier.

## ADR-009 Session tokens, not JWT (2026-10-24)
Opaque random tokens; DB stores only SHA-256. Instant revocation (logout, password
change revokes all, org suspension kills sessions). Browser: HttpOnly SameSite=Strict
cookie + required `X-Requested-With` header for writes (CSRF). Mobile/integrations:
`Authorization: Bearer`. Passwords: scrypt (stdlib), parameters stored per hash.

## ADR-010 Entitlements are central and platform-controlled (2026-10-24)
`org_entitlements` + `usage_counters` decide which tools an org can use and AI limits.
Tools call `require_feature` / `consume_usage`; none implements its own subscription
logic. Only the platform operator (CLI now, admin console later) can change
entitlements — a pharmacy owner cannot grant himself features.

## ADR-011 No frontend build chain (2026-10-24)
Vanilla JS modules + CSS, strict CSP (`script-src 'self'`, no inline). Maintainable by
one person, nothing to break on dependency updates. Revisit if the UI grows beyond ~5
complex screens.

## ADR-012 Clinical content only from licensed, versioned sources (2026-10-24)
No dose, interaction or contraindication is written from memory or generated by an LLM.
The safety engine stores each fact with its source, source version and review status;
an unreviewed rule cannot fire as "safe". See `CLINICAL_DATA_SOURCES.md`.

ملحق المشروع: استيراد بيانات الصيدليات والتوسع المستمر في الأدوات

أولًا: أداة نقل البيانات من الأنظمة الحالية (Data Migration)

أريد تطوير أداة تتيح للصيدليات الانتقال من برامج إدارة الصيدليات الحالية إلى منصتنا بأقل مجهود وأقل احتمال لفقدان البيانات.

يجب أن تدعم الأداة، بحسب البيانات التي يسمح النظام القديم بتصديرها:

- قاعدة بيانات الأصناف وأكوادها وأسمائها وباركوداتها.
- الأرصدة والكميات الحالية.
- تواريخ الصلاحية وأرقام التشغيلات عند توافرها.
- أسعار الشراء والبيع وتكاليف المخزون.
- بيانات الموردين وأرصدتهم.
- بيانات العملاء وسجلاتهم المسموح بنقلها.
- أرصدة العملاء الآجلة والمستحقات.
- فواتير المشتريات والمبيعات وسجلات المرتجعات عند توافرها.
- بيانات الموظفين والمستخدمين، دون نقل كلمات المرور بصورة غير آمنة.
- إعدادات الصيدلية والتصنيفات والبيانات الأخرى القابلة للنقل.

طرق استيراد البيانات

ادرس دعم الطرق التالية:

1. استيراد ملفات Excel وCSV.
2. استيراد ملفات JSON أو XML عند توافرها.
3. قراءة تقارير التصدير التي يوفرها البرنامج القديم.
4. التكامل عبر API رسمي إذا كان متاحًا ومصرحًا باستخدامه.
5. إنشاء أدوات استيراد مخصصة للبرامج الشائعة بعد دراسة تنسيقات بياناتها الفعلية.

لا تفترض إمكانية الوصول المباشر إلى قاعدة بيانات أي برنامج منافس، ولا تتجاوز أنظمة الحماية أو شروط الاستخدام.

خطوات نقل البيانات

يجب أن تمر عملية النقل بالمراحل التالية:

1. تحديد مصدر البيانات ونوع الملف أو النظام القديم.
2. قراءة البيانات وتحليل بنيتها.
3. مطابقة الحقول مع هيكل قاعدة بيانات منصتنا.
4. توحيد أسماء الأصناف والباركودات والوحدات قدر الإمكان.
5. اكتشاف الأصناف المكررة والبيانات الناقصة والمتعارضة.
6. عرض تقرير مسبق يوضح عدد السجلات التي ستُنقل والمشكلات المكتشفة.
7. السماح للمستخدم بمراجعة البيانات وتصحيحها.
8. تنفيذ تجربة استيراد دون تعديل البيانات الفعلية.
9. إجراء عملية الاستيراد بعد موافقة المستخدم.
10. مطابقة الأرصدة والأعداد والإجماليات قبل النقل وبعده.
11. إصدار تقرير نهائي بالنجاح والأخطاء والسجلات التي تحتاج إلى مراجعة.

يجب أن تدعم الأداة الاستيراد التجريبي، ومنع تكرار السجلات عند إعادة المحاولة، والتعامل الآمن مع فشل العملية في منتصفها.

لا تحذف البيانات من النظام القديم، ولا تغيّرها، ولا تعتبر النقل مكتملًا إلا بعد التحقق من سلامة البيانات.

ضوابط خاصة

- لا تخلط بين الرصيد الافتتاحي وحركة المبيعات والمشتريات التاريخية.
- لا تستنتج تواريخ الصلاحية أو التشغيلات المفقودة بالتخمين.
- لا تعتبر تشابه أسماء الأصناف دليلًا كافيًا على تطابقها.
- افصل البيانات التي تم التحقق منها عن البيانات التي تحتاج إلى مراجعة.
- تعامل مع بيانات العملاء والمرضى وفق متطلبات الخصوصية والموافقات والالتزامات القانونية المعمول بها.
- وفّر إمكانية تصدير بيانات الصيدلية من منصتنا بصيغ منظمة لتسهيل انتقالها مستقبلًا إلى أنظمة أخرى.

ثانيًا: نظام توسع مستمر وإضافة أدوات جديدة

يجب تصميم المنصة باعتبارها مشروعًا مستمر التطوير، وليس برنامجًا ثابتًا بعد إطلاقه.

سأقوم بإرسال أفكار ومتطلبات جديدة بصورة متكررة، وقد تشمل:

- أدوات جديدة لإدارة الصيدلية.
- أدوات ذكاء اصطناعي وتحليل بيانات.
- تقارير إضافية.
- تكاملات مع شركات وأنظمة خارجية.
- تحسينات في المبيعات والمشتريات والجرد.
- أدوات لإدارة مجموعات الصيدليات والخدمات المشتركة.

عند استلام أي فكرة جديدة، يجب عليك:

1. تحليل المشكلة التي تحاول الفكرة حلها.
2. تحديد الأداة أو الوحدة المناسبة لتنفيذها.
3. تحديد البيانات التي تحتاج إليها والبيانات التي ستنتجها.
4. التحقق من إمكانية استخدام المكونات الموجودة بدلًا من إعادة بنائها.
5. تحديد تأثيرها على قاعدة البيانات والواجهات والصلاحيات والأمان.
6. توضيح التكاليف التشغيلية والاعتماديات الخارجية إن وجدت.
7. اقتراح طريقة تنفيذ واختبارات قبول واضحة.
8. تنفيذها كجزء متوافق مع المعمارية الحالية بعد اعتماد الخطة.

قواعد إلزامية عند إضافة أي أداة

- تستخدم الأدوات قاعدة البيانات المشتركة والكيانات الموحدة كلما كان ذلك مناسبًا.
- لا تنشئ قاعدة بيانات منفصلة لكل أداة دون مبرر معماري واضح.
- لا تكرر بيانات الأصناف والعملاء والموردين في جداول مستقلة بلا حاجة.
- استخدم واجهات API وعقود بيانات موثقة عند التواصل بين المكونات.
- حافظ على التوافق مع الأدوات السابقة.
- لا تسمح للأداة الجديدة بتجاوز الصلاحيات أو قواعد السلامة.
- نفّذ اختبارات للتكامل والانحدار قبل اعتماد التعديلات.
- حافظ على توثيق المعمارية والقرارات والاختبارات والإصدارات.
- اجعل تعطيل الأداة أو تحديثها ممكنًا دون تعطيل بقية النظام متى كان ذلك مناسبًا.

تطوير البرنامج من خلال الذكاء الاصطناعي

يمكن استخدام نماذج الذكاء الاصطناعي لتحليل الأفكار الجديدة، وتصميم الأدوات، وكتابة الكود، وإعداد الاختبارات والتوثيق.

لكن لا تسمح لأي نموذج بتعديل النظام الإنتاجي أو قاعدة البيانات أو قواعد الحسابات والصلاحيات مباشرة دون مراجعة واختبارات وموافقة مخولة.

يجب أن تكون لكل إضافة جديدة معايير قبول واضحة وإمكانية الرجوع إلى الإصدار السابق عند حدوث مشكلة.

ثالثًا: الحفاظ على استمرارية المشروع

أنشئ وثيقة مركزية محدثة تحتوي على:

- الرؤية الكاملة للمشروع.
- الأدوات الحالية والمخطط لها.
- معمارية النظام وقاعدة البيانات.
- المكونات المشتركة وواجهات API.
- سجل الأفكار الجديدة والقرارات المعتمدة.
- حالة تنفيذ كل أداة.
- الاختبارات ونتائجها والمشكلات المعروفة.
- خطة العمل التالية.

حدّث الوثيقة بعد كل مرحلة، بحيث يمكن استكمال المشروع باستخدام Claude أو ChatGPT أو أي أداة تطوير أخرى دون فقدان القرارات السابقة أو إعادة تحليل المشروع من البداية.

الهدف: أن نتمكن من إضافة أدوات جديدة باستمرار، مع الحفاظ على منصة موحدة ومترابطة، وقاعدة بيانات مشتركة، وتوافق كامل مع الوظائف الموجودة، بدلًا من تحول المشروع إلى مجموعة برامج منفصلة يصعب صيانتها.

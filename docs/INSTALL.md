# التثبيت على جهاز صيدلية (Windows)

## صيدلية جديدة
1. افتح صفحة **Releases** في المستودع ← **منصة الصيدلية — آخر نسخة** ← نزّل `PharmacySetup.exe`.
2. دبل كليك ← **Next** ← اختار لو عايز البرنامج يشتغل مع الجهاز ← **Install** ← **Finish**.
3. البرنامج يفتح في المتصفح على **شاشة الترحيب**: اسم الصيدلية، والمستخدم، وكلمة السر.
4. بعدها: نقل البيانات من البرنامج القديم.

- البرنامج بيتثبت للمستخدم الحالي (من غير صلاحيات مدير) في `%LOCALAPPDATA%\Programs\PharmacyPlatform`.
- **البيانات في مكان منفصل:** `%LOCALAPPDATA%\PharmacyPlatform` (`data`، `backups`، `logs`). إعادة التثبيت أو الحذف ما بتلمسهاش.
- أيقونة على سطح المكتب، والبرنامج يفتح من غير شاشة سودا. لو اتفتح مرتين، التاني بيفتح المتصفح بس.

## نقل صيدلية شغالة (جهاز جديد، أو من النسخة القديمة اللي بالأوامر)
1. على البرنامج القديم: `python manage.py backup` (أو آخر ملف في `backups\`).
2. ثبّت `PharmacySetup.exe`، وفي شاشة الترحيب اختار **"عندك بيانات من قبل؟"** وارفع ملف `pharmacy-backup-....zip`.
3. البرنامج بيراجع الملف، ويعيد تشغيل نفسه، ويسترجع. تدخل بنفس المستخدم وكلمة السر.

## التحديث
- من جوه البرنامج: **البرنامج** (للمالك) ← **حدّث البرنامج دلوقتي**. محتاج مفتاح GitHub للقراءة (`docs/UPDATE.md`).
- لو التحديث فيه مكتبات جديدة أو تغيير في قاعدة البيانات، زرار التحديث بيرفضه، وده مقصود. ساعتها نزّل ملف التثبيت الجديد وثبّته فوق القديم.
- **أول انتقال** من النسخة القديمة (`install.bat`) بيتم بملف التثبيت بس، مش بزرار التحديث (`UPDATE.md`).

## إزاي ملف التثبيت بيتبني
`.github/workflows/windows-installer.yml` على كل push لـ main (وبتشغيل يدوي على أي فرع تاني بيطلع الملف كـ artifact من غير نشر): اختبارات على Windows ← Python مدمج + المكتبات ← اختبار تشغيل للنسخة المدمجة (selftest + init + verify) ← Inno Setup ← Release اسمه `installer-latest`.

## الحالة
- اتختبر هنا (Linux): المشغّل، والتشغيل لمرة واحدة، وإعادة التشغيل بعد الاسترجاع، والاسترجاع من نسخة احتياطية.
- اتختبر على GitHub (Windows): البناء والاختبارات وتشغيل النسخة المدمجة (لما الـ Release يظهر).
- **ما اتجربش لسه على جهاز الصيدلية:** التثبيت نفسه، والأيقونة، والتشغيل مع الجهاز.

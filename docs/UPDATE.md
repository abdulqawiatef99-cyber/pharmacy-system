# التحديث التلقائي (#96) — من غير زرار ومن غير تنزيل مثبّت بإيدك

**مرة واحدة بس:** أول نسخة فيها التحديث التلقائي لازم تتثبت بالمثبّت يدويًا (النسخ الأقدم مش بتعرف تحدّث نفسها لقناة develop). بعدها كل حاجة لوحدها. مفتاح القراءة من GitHub (`~/.pharmacy/github_token.txt`) لازم يكون موجود (الطريقة تحت).

## بيعمل إيه
- **البحث:** عند فتح البرنامج (بعد دقيقة) وكل 4 ساعات (الإعدادات ← البرنامج: 1–24 ساعة).
- **التثبيت لوحده، وقت ما يكون آمن بس:**
  - أبدًا وفيه فاتورة بيع مفتوحة (مسودة فيها أصناف اتفتحت في آخر ساعة)، أو أي عملية بيع في آخر 5 دقايق، أو **وردية مفتوحة**. مسودة قديمة مركونة مش بتوقف التحديث: بتفضل محفوظة في قاعدة البيانات بعد إعادة التشغيل. الزرار كمان بيستنى الوردية تتقفل.
  - برا ساعات الشغل بس: وقت الهدوء (افتراضي 03:00–06:00، يتغير من الإعدادات). أول 15 دقيقة بعد فتح البرنامج وإغلاق الوردية بيحسبوا **لو المالك فعّلهم بس** (اختيار «كمان بعد قفل الوردية وأول ما البرنامج يفتح»، مقفول افتراضيًا). أي وقت تاني: مستني زرار «حدّث الآن» (موافقة المالك).
  - أول ما نسخة جديدة تظهر ومش هتتركب دلوقتي: إشعار واحد بالعربي فيه اللي اتغير وإمتى هيتركب لوحده، وإن الزرار موجود.
  - إعادة تشغيل اتأجلت عشان بيع بدأ في النص: بتحصل لما البيع يخلص، في وقت مسموح أو لو المالك هو اللي داس الزرار.
  - وقت إعادة التشغيل (ثواني) طلبات البيع الجديدة بترجع «البرنامج بيتحدث، أعد المحاولة».
- **تحديث كود** (التغيير مش في المكتبات ولا الـ migrations ولا launcher/bootstrap ولا ملفات المثبّت): `manage.py update --ref <القناة> --sha <commit>` ← التأكد إن الملف المتنزّل سليم (CRC) وإنه نفس الـ commit المطلوب (اسم المجلد + تعليق الـ zip) ← نسخة احتياطية متأكد منها ← فحص النسخة الجديدة (`selftest --quick`) على بيانات مؤقتة ← اختيار ذري ← إعادة تشغيل. الـ launcher بيشغّل `selftest --quick` على النسخة المختارة وبعدين فحص البدء؛ لو أي واحد فشل **بيرجع للنسخة السابقة لوحده**.
- **تحديث بالمثبّت** (تغيّر `requirements.txt` أو `app/migrations/` أو `launcher.py` أو `release_bootstrap.py` أو `release_protocol.json` أو `installer/` أو workflow المثبّت/نسخة Python): البرنامج بينزّل `PharmacySetup.exe` من release القناة بنفس المفتاح (المفتاح بيروح لـ api.github.com بس)، ويتأكد من sha256 مقابل `installer.json` وبصمة GitHub، وياخد نسخة احتياطية متأكد منها، ويشغّل `PharmacySetup.exe /SILENT /SUPPRESSMSGBOXES /NORESTART /RELAUNCH=1 /LOG=...` كعملية مستقلة. المثبّت بيقفل البرنامج، يثبّت، ويفتحه تاني لوحده (`/RELAUNCH=1`، حتى لو التثبيت فشل). **مفيش رجوع تلقائي للمثبّت** (الـ migrations ممكن تكون اتطبقت): لو فشل، الإشعار بيقول كده وفيه اسم النسخة الاحتياطية ومسار السجل `data\updates\install-*.log`.
- **بعد إعادة التشغيل:** إشعار واحد: «تم تحديث البرنامج تلقائيًا: نسخة X (sha)» + اللي اتغير (عناوين الـ PRs). لو فشل: إشعار خطأ بالسبب، والنسخة دي مش بتتجرب تاني لوحدها (نسخة أحدث أو زرار «حدّث الآن» بيجرّبوا).

## القنوات
- `main` = الصيدلية (الافتراضي). مفيش حاجة بتوصل `main` غير بموافقة المالك (AGENTS §2)؛ ده ماتغيرش.
- القناة مابتتغيرش لوحدها أبدًا: يا إما قناة المثبّت/آخر تحديث، يا إما اللي المالك اختاره من الإعدادات (بيتسجل في سجل العمليات). نسخة develop من غير «قناة» = نفس قاعدة #107 (`updater.channel`).
- `develop` = جهاز التجربة بس. بتتاح لو البرنامج متثبت من مثبّت develop، أو فيه ملف `~/.pharmacy/test_pc` على الجهاز. مثبّت develop بيتبع develop لوحده (اتشال الطريق المسدود القديم `ref != main`).
- مثبّت من أي فرع تاني = نسخة مراجعة: مش بتتحدث لوحدها إلا لو المالك اختار قناة.
- كل push لـ `main` بينشر `installer-latest`، وكل push لـ `develop` بينشر `installer-develop` (prerelease)، والاتنين فيهم `installer.json` (commit، الفرع، sha256، الحجم). تعديل docs بس مش بيبني مثبّت؛ التحديث بيكمّل بالكود.

# تحديث الكود الآمن — بروتوكول 1 (فرع مراجعة، غير معتمد للتشغيل)

الانتقال الأول من المحدّث القديم يحتاج مُثبّتًا موثوقًا والبرنامج مغلقًا، بعد مراجعة واعتماد صاحب المشروع. لا تستخدم المحدّث القديم لتثبيت هذا الإصلاح.

- يتم تجهيز الكود في مجلد مستقل داخل `PHARM_DATA_DIR/code-releases`، والتحقق من الملفات وتشغيل فحص أولي ببيانات مؤقتة.
- يُرفض الإصدار إذا غيّر المكتبات أو ملفات SQL للترحيلات؛ هذه التغييرات تحتاج خطة ترقية منفصلة.
- لذلك `requirements.txt` مثبّت بإصدارات محددة (`==`): أي تعديل فيه أو أي migration جديد ينزل **بالمثبّت فقط**، مش بزرار التحديث.
- المثبّت بيكتب `build_info.json` (الـ commit والفرع). أول تشغيل بعد تثبيت مثبّت جديد بيشغّل البرنامج المثبّت بدل أي نسخة كانت اتنزلت بزرار التحديث قبل كده (مرة واحدة لكل مثبّت؛ التحديث اللي بعده بيفضل شغال). شارة "تحديث" مش بتظهر لمثبّت من `main` نفسه، ولا لمثبّت تجربة من فرع تاني (#45).
- تُنشأ نسخة بيانات احتياطية إن وُجدت قاعدة البيانات، ثم يُبدّل مؤشر الإصدار ذريًا. لا يجري استبدال ملفات البرنامج المفتوحة.
- أول تشغيل يكون عبر launcher؛ يجب أن يجيب الإصدار الجديد عن فحص الصحة بمعرّف عملية البدء. عند فشله يرجع مؤشر الكود السابق.
- الرجوع اليدوي: `python manage.py update --rollback` باستخدام نفس `PHARM_DATA_DIR`. الرجوع للكود فقط؛ لا يستعيد قاعدة البيانات ولا يحذف معاملات أحدث.
- لا تشغّل `serve` مباشرة لإصدار ينتظر فحص البدء. استخدم launcher أو تراجع عن التحديث.
- لا تُحذف الإصدارات السابقة تلقائيًا. تحقق Windows الفعلي والتوقيع والترقيات المنسقة لم تُنجز ضمن هذا الإصلاح.

التعليمات التاريخية التالية تخص المحدّث القديم فقط، وليست تعليمات تشغيل لهذا الفرع.

# تحديث البرنامج على جهاز الصيدلية

## مرة واحدة: مفتاح القراءة من GitHub
المستودع Private، فالجهاز محتاج مفتاح **للقراءة بس**:
1. github.com ← الصورة الشخصية ← **Settings** ← **Developer settings** ← **Personal access tokens** ← **Fine-grained tokens** ← **Generate new token**.
2. الاسم: `pharmacy-pc-update`. المدة: سنة. **Repository access: Only select repositories** ← `pharmacy-system`.
3. **Permissions ← Repository permissions ← Contents: Read-only** (وسيب الباقي No access).
4. انسخ المفتاح واحفظه في الملف: `C:\Users\<اسم المستخدم>\.pharmacy\github_token.txt` (سطر واحد).
   - الملف **برّا فولدر البرنامج**: مش بيترفع، ومش بيدخل في النسخ الاحتياطية.
   - لو المفتاح اتسرب: امسحه من نفس الصفحة على GitHub واعمل واحد جديد.

## كل مرة
اقفل شاشة البرنامج، وبعدين دبل كليك على `scripts\windows\update.bat`. الأمر بيعمل بالترتيب:
1. يشوف آخر نسخة على GitHub، ولو البرنامج محدّث يقول كده ويخرج.
2. **نسخة احتياطية متأكد منها للبيانات** في `backups\`؛ لو فشلت، التحديث بيتلغي.
3. نسخة من البرنامج الحالي في `backups\code-before-update-*.zip` (للرجوع).
4. ينزّل النسخة الجديدة ويتأكد إنها سليمة قبل ما يكتب أي ملف، وبعدين يحطها مكان القديمة. **فولدرات `data` و`backups` و`.venv` ما بتتلمسش.**
5. يثبّت المكتبات (لو قايمتها اتغيرت)، ويطبّق تحديثات قاعدة البيانات، ويعمل `verify` و`selftest --quick`.

## الرجوع لنسخة قديمة
```
python manage.py update --from-zip backups\code-before-update-YYYYMMDD-HHMMSS.zip
```
ولو البيانات نفسها محتاجة ترجع: `python manage.py restore backups\pharmacy-backup-....zip --yes`.

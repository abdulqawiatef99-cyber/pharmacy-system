# الإضافات المستقبلية — Future Requirements

هنا بتتسجل أي فكرة جديدة بتوصل وأنا شغال. **مفيش فكرة منهم بتتنفذ لوحدها.**
بعد كل مرحلة بنراجع القايمة دي ونرتب الأولويات، وأي تنفيذ محتاج موافقة صريحة منك.
الحالة ممكن تكون: مسجلة / مرتبة / معتمدة للتنفيذ / منفذة.

| # | الفكرة | ليه مهمة | الجزء اللي هتأثر عليه | تأثيرها على التصميم الحالي | الحالة |
|---|---|---|---|---|---|
| F1 | تطبيق موبايل خاص بالصيدلية | قناة طلبات مباشرة للعملاء | المبيعات، العملاء، الـ API | مفيش تأثير. الـ API بيدعم Bearer tokens من دلوقتي (`docs/API.md`) | مسجلة |
| F2 | التكامل مع طلبات (Talabat) | قناة بيع إضافية | المبيعات، الأصناف، المخزون | محتاج جدول outbox وحساب شريك. اتخطط في ARCHITECTURE §6 | مسجلة |
| F3 | التكامل مع إنستاشوب | قناة بيع | زي F2 | ملقيناش API عام، ومحتاجين نتواصل معاهم | مسجلة |
| F4 | خدمة للمخازن وشركات الأدوية (B2B) | منتج تاني | الصيدليات والمنظمات | `organizations.org_type` بيدعم warehouse/company من دلوقتي | مسجلة |
| F5 | أخبار وتنبيهات هيئة الدواء والتفتيش | التزام قانوني | تنبيهات السحب | جزء السحب اتنفذ بإدخال يدوي. الجلب الأوتوماتيك والتفتيش لسه | جزء منها منفذ |
| F6 | متجر Cosmo أونلاين | بيع مستحضرات التجميل | الأصناف، المبيعات | يستخدم نفس الأصناف والمخزون، من غير قاعدة بيانات منفصلة | مسجلة |
| F7 | الوصف الذكي والصوت (الملحق الطبي) | دعم القرار | السلامة | البنية التحتية جاهزة، والمحتوى متوقف على قرار المصدر | متوقفة على قرار |
